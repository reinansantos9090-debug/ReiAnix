# ReiAnix monetization

- Official APK and AAB builds from the main CI workflow always use production mode. They never grant simulated Premium or request sample ads. PR/debug/benchmark builds keep isolated preview state and Google sample ads.
- Create and activate the non-consumable one-time product `reianix_premium` in Play Console, set the Brazil base price to R$ 9.90, then copy the app's RSA billing public key to GitHub Settings > Secrets and variables > Actions > Variables > `REIANIX_BILLING_PUBLIC_KEY`. This is the public licensing key, not the private signing key. The official workflow reads it automatically. Missing key leaves purchases unavailable rather than simulating them; an invalid key fails the build.
- Build and upload a new signed AAB from main. Test through a Play internal/closed track with license testers and Google test payment methods; real BillingClient integration does not mean testers must pay. Price comes from Play. Do not consume the product.
- Five real AdMob placements are configured. After applicable AdMob review, UMP consent messages, app-ads.txt, privacy policy, Data Safety and rights checks, set repository Actions variable `REIANIX_ENABLE_LIVE_ADS` to `true` and rebuild. Until then official artifacts request no ads, not sample ads. Use designated test devices; never click live ads.
- Real purchases are verified locally using Google's RSA signature and acknowledged; purchases are queried on foreground to recover/refund state. Client-only verification is not tamper-resistant; secure backend verification is recommended before public monetization.
- No ads in the player. Existing Premium benefits, local library and playback are unchanged. DAY rewards grant temporary Premium for 24h; art rewards remain local. Preview entitlements never migrate into production.
- Local production build flags: `-PreianixProductionBuild=true -PreianixBillingPublicKey=<public key>`; add `-PreianixEnableLiveAds=true` only when ready. PR builds cannot opt into production.
- Verify real purchase, restore, cancellation, pending purchase, refund, consent, no-fill, offline, restart and expiry on-device before public distribution.
